# EpicLens System - Modern Architecture & Security Blueprint

EpicLens System is a high-performance, secure campus event equipment lending and return tracking platform.

---

## 1. Resolved Issues from Legacy Version

| Area | Legacy Problem | Modern Solution in EpicLens |
| :--- | :--- | :--- |
| **CSRF Security** | State changes (equipment deletion, user status toggling, event resets) executed via `GET` requests with zero CSRF protection. | Comprehensive `Csrf` token management. State modifications strictly require `POST` with `Csrf::requireValid()` verification. |
| **Credential Safety** | Hardcoded hosting usernames and passwords directly inside `config/database.php`. | Configurable `.env` environment architecture with committed `.env.example` and strict `.gitignore` exclusion. Zero credentials leaked. |
| **Data Privacy** | Real student names, phone numbers, and sample transaction data bundled in `schema.sql`. | Pure DDL schema in `database/schema.sql` with zero personal or sample records. Added git rules preventing user data commits. |
| **Database Performance** | `ensureSchemaUpToDate()` ran multiple `SHOW COLUMNS` and `ALTER TABLE` queries on **every single page request**. | Schema setup decoupled from request lifecycles. Handled via one-time installer (`setup.php`) or CLI runner (`database/migrate.php`). |
| **SQL Syntax Errors** | SQL syntax error (`USE '...;`) broke standard phpMyAdmin and CLI imports. | Clean, standardized, portable MySQL DDL with UTF-8 (`utf8mb4_unicode_ci`) collation. |
| **Information Disclosure** | Unauthenticated `debug.php`, `test.php`, and `db_test.php` scripts exposed server software, PHP version, and internal tables. | Insecure debug endpoints removed from web root. Production-grade error masks without credential leakage. |
| **Session Security** | Loose sessions vulnerable to fixation and hijacking. | Enforced strict mode, `HttpOnly` and `SameSite=Lax` cookies, with session regeneration on authentication. |

## 2. 4-Stage Operational Workflow

The system cleanly separates permanent student equipment ownership from temporary event crew usage through a 4-step sequence:

```
┌────────────────────────────────────────────────────────┐
│ 1. RECEIVE FROM STUDENT OWNER                          │
│    Staff check-in at event desk                        │
│    Event User: Unassigned                              │
│    Equipment Status: Received                          │
└───────────────────────────┬────────────────────────────┘
                            │ Staff clicks [ ASSIGN CREW ]
                            ▼
┌────────────────────────────────────────────────────────┐
│ 2. ASSIGN EVENT CREW MEMBER                            │
│    Crew member name & phone recorded                   │
│    Equipment Status: Received (Active In Use)          │
└───────────────────────────┬────────────────────────────┘
                            │ Crew member returns gear
                            │ Staff clicks [ CREW RETURN ]
                            ▼
┌────────────────────────────────────────────────────────┐
│ 3. EVENT CREW RETURNS TO EVENT TEAM                    │
│    Team receives equipment back, logs condition        │
│    Equipment Status: Received (Ready for Owner)        │
└───────────────────────────┬────────────────────────────┘
                            │ Staff clicks [ RETURN TO OWNER ]
                            ▼
┌────────────────────────────────────────────────────────┐
│ 4. FINAL RETURN TO STUDENT OWNER                       │
│    Equipment handed back to permanent owner            │
│    Equipment Status: Returned (Lending Cycle Complete) │
└────────────────────────────────────────────────────────┘
```

---

## 3. Strict 3 Event Statuses

Every piece of equipment in the event inventory exists in exactly one of these 3 statuses:
1. **`Not Received Yet`**: Expected at event start; owner has not arrived at check-in.
2. **`Received`**: Equipment is held in custody of the event team.
3. **`Returned`**: Equipment has been formally handed back to its student owner.

Mathematical consistency:
$$\text{Total Equipment} = \text{Not Received Yet} + \text{Received} + \text{Returned}$$

## 4. Item Code Sequence Engine

Every item is assigned a permanent, unique Item Code generated by category prefixes:
- **`CM`**: Camera (`CM001`, `CM002`...)
- **`TP`**: Tripod (`TP001`, `TP002`...)
- **`LN`**: Lens (`LN001`, `LN002`...)
- **`GM`**: Gimbal (`GM001`, `GM002`...)
- **`MC`**: Microphone (`MC001`, `MC002`...)
- **`FL`**: Flash (`FL001`, `FL002`...)
- **`LT`**: Light (`LT001`, `LT002`...)
- **`OT`**: Other (`OT001`, `OT002`...)

Atomic sequence numbers are tracked in `item_code_sequences`. Deleted codes are never recycled, preserving immutable audit logs.
